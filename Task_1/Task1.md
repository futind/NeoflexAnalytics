# Задание
Опишите функциональные и нефункциональные требования для форм «Хочу учиться» и «Набор закрыт» на сайте Учебного Центра Neoflex https://edu.neoflex.ru/ (форма открывается по кнопке «Хочу учиться» - кнопка неактивна в момент активного набора в Учебный центр).

## Форма "Хочу учиться", когда набор открыт, вместо ТГ-бота
### Функциональные требования
1. Поля
	1. ФИО - обязательное поле.
	2. Электронная почта (допустим, в формате rfc 2821) - обязательное поле.
	3. Номер телефона с drop-down меню, где можно выбрать телефонный код своей страны
		1. (Вопрос к заказчику - планируется ли набор вне РФ? Допустим, заказчик сказал, что да) - обязательное поле.
	4. Выбор интересующего направления через drop-down меню (combobox) - обязательное поле.
	5. Выбор города проживания - Drop-down меню с возможностью заполнения - обязательное поля.
	- В случае незаполнения обязательных полей - подсветить над этими полем надпись "Поле обязательно для ввода".
2. Кнопка "отправить", вызывающая следующее модальное окно с подтверждением регистрации с помощью кода, отсылаемого на электронную почту.
	1. В модальном окне есть поле ввода кода - обязательное (в случае отсутствия показать надпись "Поле обязательно для ввода")
	2. Кнопка "Подтвердить".
	3. Ниже - маленькая кнопка в виде текста "Отправить ещё раз" с таймером в три минуты между попытками 
		- В случае несовпадения кода сверху от поля ввода кода высвечивается текст "Неверный код"
		- При успешной верификации электронной почты выдаём сообщение пользователю о том, что заявка принята успешно, дальнейшие инструкции будут высланы ему на указанный адрес электронной почты
3. Показывать ссылки о согласии с политикой обработки персональных данных и политикой конфиденциальности.
### Нефункциональные требования
1. Сохранение заполненных полей в одной сессии браузера
2. Какая цветовая гамма у формы? Заказчик: форма фиолетового цвета, кнопки оранжевого цвета, поля более тусколого оттенка фиолетового,  шрифт на фиолетовом - белый, в полях - серый, текст в полях, вводимый пользователем - белый, текст на кнопках - чёрный.
3. Шифрование данных при передаче на сервер.
4. Адаптивный интерфейс под разные устройства и браузеры
5. Какое должно быть время ответа на запрос о предоставлении кода подтверждения? Заказчик - 1 минута.
6. Какое минимальное количество запросов в секунду (rps) должна обрабатывать система? Заказчик - 100 запросов.
7. Какой процент времени система должна работать без отказов? Заказчик - 99.5% времени.
8. В какие часы система должна работать и быть доступной для запросов? Заказчик - круглосуточно.
